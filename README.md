# Codex Helper

> 你舍不得骑的自行车，别人站起来蹬，codex helper，帮你站起来蹬！

Codex Helper 是一个跑在本机的 Codex 任务监控与排程助手。它盯着正在工作的任务，记住你想做的下一步，在额度恢复、前一项任务结束或指定时间到达时，替你把下一句 Prompt 送回正确的 Codex 对话。

简单说：你负责提出宏伟目标，Codex 负责写代码，Codex Helper 负责在大家都快忘了这件事的时候把工作接起来。

## 它主要解决什么问题

### 1. 任务结束了，下一步不用靠记忆

在“任务排程”选项卡中选择“发送下一步”，按 Codex 的 **项目 → 任务** 层级找到具体工作，填写下一步 Prompt。当前任务结束后，Helper 会向同一对话追加一轮。

如果任务已经结束，保存后立即执行；如果任务仍在运行，就等当前轮完成后再发送。任务选择器包含本机所有未归档的 work 任务，也包含较早结束的任务。

### 2. 额度用完了，别让工作躺平

> 白花花的token 额度，都散给了 sam altman，造孽啊！

“续跑任务”可以接住被额度限制打断的工作。Helper 会监控任务状态；额度恢复后，继续向原对话发送 Prompt。已结束的任务也可以手动选择并立即续跑。

还可以开启“额度恢复后自动续跑”：只监控开关打开之后发生的额度中断，避免把多年前的遗憾突然复活。

### 3. 新任务按计划启动

启动新任务时可以：

- 在指定时间运行；
- 下一次额度刷新后运行；
- 等另一项正在运行的任务结束后运行；
- 选择已有的本地 Codex 项目；
- 创建一个新项目目录并在其中运行。

排程队列会显示等待中、执行中和历史规则，等待中的规则可以取消。

## 界面怎么组织

- **总览**：额度水位、模型使用、错误和本地监测数据；
- **任务监控与排程**：任务状态、自动续跑开关、项目 → 任务选择器和排程队列；
- **任务选择器**：先选项目，再选具体对话，避免把项目名误当成任务；
- **历史规则**：查看已完成、失败、取消或需要检查的排程。

后台每 5 秒扫描一次本地任务状态。总览页的额度水位每 60 秒刷新；存在等待额度的排程时，后台约每 10 秒查询一次实时额度。点击面板右上角刷新按钮可以立即刷新当前页面。

## 安装

### macOS Apple Silicon

下载 [Codex Helper ARM64 DMG](https://github.com/Allencheng97/codex-helper/releases/latest)，拖入“应用程序”后启动。当前构建未经过 Apple Developer ID 签名，首次打开时可在 Finder 中右键选择“打开”。

也可以从源码构建：

```bash
npm install
npm run dist
```

生成的安装包位于 `dist/Codex Helper-*.dmg`。

### 从源码运行

要求 Python 3.8+、Node.js 和本机已登录的 `codex` CLI：

```bash
git clone https://github.com/Allencheng97/codex-helper.git
cd codex-helper
npm install
npm start
```

开发模式也可以直接运行本地服务：

```bash
python3 codex_model_watch.py --no-open
```

所有服务只监听 `127.0.0.1`。排程执行依赖本机的 Codex 登录态和 `codex` CLI，应用退出或电脑睡眠时不会偷偷补跑；重新启动后，未完成的执行规则会标记为“需检查”。

## 数据与隐私

任务状态来自本机 Codex 的会话索引和 rollout 日志，排程规则保存在：

```text
~/.codex-model-watch/state.db
```

项目目录、Prompt 和任务标题不会上传到第三方。Helper 不提供云端队列，也不会替你把 Prompt 发给任何额外的服务；实际执行仍使用你当前登录的 Codex CLI。

## 监测功能从哪里来

Codex Helper 的总览、模型用量、额度窗口、容量错误和主动探针能力，继承并扩展自 [ysh1112/codex-model-watch](https://github.com/ysh1112/codex-model-watch)。感谢原作者 ysh1112 提供本地 Codex 会话日志解析、用量统计和模型探针的基础实现。

本项目在此基础上加入了 Electron 菜单栏应用、任务状态监控、项目 → 任务选择、额度恢复续跑、下一步 Prompt、一次性排程和可视化队列。原项目的监测能力仍然保留，只是现在终于有人负责在额度见底时提醒大家别继续硬蹭了。

## 监测能力

- 从本地会话日志统计模型、轮次、token、耗时和错误；
- 显示 5 小时 / 7 天额度窗口；
- 记录容量拒单和额度限制错误；
- 使用主动探针检查请求模型与实际派出模型是否一致。

主动探针会消耗一条很小的 Codex 请求额度，只有你主动点击时才会发出请求。历史日志无法可靠还原过去发生的模型切换，因此探针结果只代表发起探测时的状态。

## 已知边界

- 这是本机助手，不是云端任务队列；电脑关机、睡眠或应用退出时无法触发规则；
- Codex rollout 和状态数据库属于本地内部格式，未来 Codex 版本变化可能需要适配；
- 额度水位来自 Codex 上报数据，界面展示会有刷新间隔；
- 任务选择器排除已归档任务和子代理任务；
- 新项目会在规则真正触发时创建，避免排程还没执行目录就先占坑。
